# NER_data: annotated call transcripts for zero-shot entity extraction and PCI identification

100,000 synthetic health-plan member-services calls with **gold character-offset
entity spans**, generated by `generate_ner_data.py`. Same `agent:` /
`customer:` turn format as `auth_data` and `class_data`. Built to evaluate
**zero-shot** extraction with the local GLiNER model
(`/Users/sam/models/gliner_base`) and to measure PCI / PII detection on
speech-to-text transcripts. Nothing is fine-tuned on it, although the splits
are there if that changes. All values are synthetic; card numbers, NPIs and
SSNs follow real checksum / structure rules so detectors can be tested on
plausible values.

## Record schema

```json
{
  "id": "ner_000047",
  "transcript": "agent: hi you've reached evergreen health plan my name is skyler ... customer: the number is hmm 4465-1242-8514-6351 agent: okay ending in 6351 is that right ...",
  "entities": [
    {"start": 499, "end": 518, "text": "4465-1242-8514-6351", "label": "CARD_NUMBER",
     "gliner_label": "credit card number", "pci": true, "pii": false, "format": "dashed_digits", "role": "customer"},
    {"start": 616, "end": 636, "text": "zero three three one", "label": "CARD_EXPIRATION",
     "gliner_label": "card expiration date", "pci": true, "pii": false, "format": "spoken_words", "role": "customer"}
  ],
  "contains_pci": true,
  "pci_types": ["CARD_CVV", "CARD_EXPIRATION", "CARD_NUMBER"],
  "contains_pii": true,
  "entity_counts": {"PERSON_NAME": 2, "MEMBER_ID": 1, "CARD_NUMBER": 1, "...": 1},
  "scenario": "card_payment",
  "noise_level": "medium",
  "n_turns": 23,
  "n_words": 141,
  "split": "test"
}
```

`transcript[start:end] == text` holds for every span (asserted at generation).
`format` records how the value was spoken (`raw_digits`, `grouped_digits`,
`dashed_digits`, `spoken_words`, `mixed`, `mm/yy`, `month words`, ...) so
recall can be broken down by surface form. `role` is `customer`, `agent`,
`provider` or `dependent`.

## How values are rendered

* **Card numbers**: Luhn-valid Visa / Mastercard / Discover (16 digits) and
  Amex (15 digits). 30% grouped (`4465 1242 8514 6351`), 15% raw, 10% dashed,
  30% spoken words (`four four six five ... double one`), 15% mixed. Spoken
  forms sometimes contain a filler (`um`, `hold on`) inside the span. Agents
  occasionally read back the last four digits; that fragment is **not** labelled.
  A few calls contain a corrected second card number.
* **CVV**: 3 digits (4 for Amex), raw or spoken. **Expiration**: `mm/yy`,
  `mm yy`, `mmyy`, `month yyyy`, `month words`, spoken.
* **SSN**: valid area/group/serial structure; dashed, grouped, raw or spoken.
* **NPI**: 10 digits with the real Luhn check over the `80840` prefix.
* **DOB**: words (`march third nineteen eighty two`), `month d yyyy`,
  `mm dd yyyy`, `m/d/yyyy`, spoken digits.
* **Addresses**: house number, street, optional unit, city, optional state and
  zip, with house numbers and zips sometimes spoken.
* **Noise**: light ASR noise (fillers, dropped short words, homophones,
  `[inaudible]`-style tags) is applied only **outside** entity spans, so offsets
  stay exact. `noise_level` is low 40% / medium 40% / high 20%.

## Running GLiNER zero-shot

```bash
uv run python NER_data/run_gliner.py --limit 500                    # quick look at the test split
uv run python NER_data/run_gliner.py                                 # full test split (10k calls, ~20 min on MPS)
uv run python NER_data/run_gliner.py --threshold 0.3                 # looser decision threshold
uv run python NER_data/run_gliner.py --labels-subset pci             # prompt only the three PCI labels
uv run python NER_data/run_gliner.py --split validation --window-words 100
```

The runner loads the model from the local directory only, splits each call
into overlapping 120-word windows (GLiNER's context is short), maps
predictions back to absolute offsets, de-duplicates across windows, and writes
`results/gliner_metrics.json` and `results/gliner_errors.jsonl`. Metrics:

* per label precision / recall / F1 with **partial** match (same label, span
  overlap >= 50%) and **exact** match;
* recall by surface `format`;
* **call-level PCI detection** (does the call contain any PCI span?) and PII
  detection, as precision / recall / F1 with the confusion counts.

### Accuracy fixes and comparison

`run_gliner.py` implements the fixes as switches, so each one can be measured
on the same calls. `--compare` runs the whole matrix and writes
`results/comparison.json` / `comparison.md`:

| Switch | What it does |
|--------|--------------|
| `--strip-speaker-tags` | blanks `agent:` / `customer:` in the model input with same-length spaces (offsets unchanged) so they stop being tagged as person names |
| `--normalize-digits` | rewrites spoken digit runs (`four four six five`, `double one`, `oh`, fillers inside the run) to digits before the model sees the text; predictions are mapped back to original offsets |
| `--rules` | deterministic layer on the normalised text: Luhn-valid 15–16 digit runs -> `CARD_NUMBER`; keyword context + pattern -> `CARD_CVV`, `CARD_EXPIRATION`, `SSN`; `npi` context + 80840-Luhn -> `PROVIDER_NPI`. Rule spans override overlapping model spans |
| `--rules-exclusive` | with `--rules`: those five labels come **only** from the rules; the model's noisy predictions for them are dropped |
| `--label-set tuned` | alternative prompt strings (`payment card number`, `cvv security code`, `doctor or clinic name`, `person's full name`, `telephone number`, ...) |

The last row is `results/gliner_metrics_best.json` (154 PCI calls and 246
non-PCI calls, zero errors at call level; micro precision 0.77, recall 0.84).
Reproduce it with:

```bash
uv run python NER_data/run_gliner.py --limit 400 --strip-speaker-tags --normalize-digits \
    --rules --rules-exclusive --label-set tuned --tag _best
uv run python NER_data/run_gliner.py --limit 400 --compare       # the whole matrix
```

What the comparison shows:

1. **Digit normalisation alone does nothing for card numbers** (0.02): even
   written as digits, the model reads a lowercase `4465 1242 8514 6351` as a
   phone number or member id. Normalisation is still the enabler for the next
   step: it is what lets the rules see spoken numbers.
2. **The rule layer is the PCI fix.** Rules alone take card numbers from 0.03
   to 0.65; rules on normalised text take them to 0.96, and `--rules-exclusive`
   to 1.00 with SSN 0.95 and NPI 0.93, because every value passes a checksum or
   a structural pattern and the model's competing guesses are discarded. PCI
   call detection goes from 0.82 to 1.00 F1.
3. **Stripping speaker tags helps names and hurts identifiers.** Person-name
   F1 rises 0.65 -> 0.80, but with the tags gone the model emits more spurious
   SSN / NPI spans on other numbers (recall unchanged, precision down). With
   `--rules-exclusive` that cost disappears, which is why the two switches
   belong together.
4. **Prompt wording is worth 0.05 micro F1.** `doctor or clinic name` lifts
   provider names from 0.25 to 0.76 and `person's full name` helps names; but
   `member id` scored 0.41 against 0.76 for `member id number`, so the tuned
   set keeps the latter. Labels need to be tuned per entity, not as a set.
5. **Addresses remain the open problem** (0.22–0.33). The model finds a
   fragment (the zip, or the street) rather than the whole span, so partial
   match at 50% overlap fails. Options: a lower overlap threshold for
   addresses, a rule that extends a predicted fragment to the surrounding
   house-number ... zip pattern, or a larger GLiNER variant.
6. **Remaining CVV misses** (0.90) are 3-digit codes spoken without a nearby
   keyword, or where the keyword window is cut by a long filler; the
   expiration gaps (0.96) are mostly the `month words` form after a long
   detour. Both are regex-window tuning, not model limits.
